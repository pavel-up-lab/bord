# Spec Delta

## Purpose

Определяет доставку уведомлений об изменениях досок и тредов в реальном времени без превращения потока событий в единственный источник данных.

## ADDED Requirements

### Requirement: Подписка на события через SSE
Система SHALL предоставлять SSE-поток для выбранной доски или треда и отправлять события создания, удаления, закрытия и обновления каталога.

#### Scenario: Новый ответ в открытом треде
- **WHEN** подписанный клиент подключен к треду и появляется видимый ответ
- **THEN** сервер отправляет событие `post.created` с идентификаторами доски, треда и поста

### Requirement: Идентификаторы событий и возобновление
Каждое событие SHALL иметь монотонный в пределах потока идентификатор, а сервер SHALL принимать `Last-Event-ID` для восполнения доступных пропущенных событий.

#### Scenario: Кратковременный разрыв
- **WHEN** клиент переподключается с еще доступным `Last-Event-ID`
- **THEN** сервер передает последующие события по порядку без намеренного дублирования

#### Scenario: История событий недоступна
- **WHEN** указанный идентификатор старше окна хранения событий
- **THEN** сервер отправляет событие `stream.reset`, после которого клиент заново получает состояние через HTTP API

### Requirement: Heartbeat и обнаружение разрыва
Система SHALL периодически отправлять SSE heartbeat, не меняющий состояние, чтобы клиенты и прокси могли обнаруживать неактивное соединение.

#### Scenario: Нет пользовательских событий
- **WHEN** в потоке отсутствуют изменения в течение настроенного интервала
- **THEN** сервер отправляет heartbeat, а клиент сохраняет подписку без перерисовки контента

### Requirement: Ограниченная доставка realtime
Система MUST рассматривать SSE как уведомление об изменении, а HTTP API — как источник актуального состояния после потерь, переподключения или неизвестного события.

#### Scenario: Неизвестный тип события
- **WHEN** клиент получает неизвестный ему тип события совместимой версии
- **THEN** клиент игнорирует событие и продолжает поток без аварийного завершения
