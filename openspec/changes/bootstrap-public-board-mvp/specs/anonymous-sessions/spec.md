# Spec Delta

## Purpose

Определяет анонимное участие без регистрации, локальную идентичность клиента и безопасное подтверждение права удалить собственную публикацию.

## ADDED Requirements

### Requirement: Анонимный доступ без аккаунта
Система SHALL разрешать чтение и публикацию без регистрации, имени, электронной почты или иного постоянного публичного профиля.

#### Scenario: Первый запуск клиента
- **WHEN** пользователь запускает клиент без локальной сессии
- **THEN** клиент создает криптографически случайный секрет сессии и сохраняет его только в пользовательском каталоге конфигурации

### Requirement: Псевдоним автора в пределах треда
Система SHALL вычислять стабильный непредсказуемый публичный идентификатор автора внутри одного треда, не позволяющий связать автора между разными тредами.

#### Scenario: Два поста одной сессии
- **WHEN** одна анонимная сессия публикует два поста в одном треде
- **THEN** оба поста получают одинаковый идентификатор автора в этом треде

#### Scenario: Публикация в другом треде
- **WHEN** та же сессия публикует пост в другом треде
- **THEN** публичный идентификатор автора отличается

### Requirement: Токен удаления владельца
Система SHALL выдавать отдельный секрет удаления для каждой созданной публикации и SHALL хранить на сервере только его стойкое проверочное представление.

#### Scenario: Удаление собственного поста
- **WHEN** клиент предъявляет действительный токен удаления видимого поста
- **THEN** система заменяет содержимое поста tombstone и делает прежнее вложение недоступным

#### Scenario: Недействительный токен
- **WHEN** клиент предъявляет неверный токен удаления
- **THEN** система отклоняет операцию без указания, какая часть токена неверна

### Requirement: Отсутствие переноса сессии сервером
Система MUST NOT предоставлять механизм восстановления анонимной сессии или токенов удаления при утрате локальных секретов.

#### Scenario: Утрата локальной конфигурации
- **WHEN** пользователь теряет локальные секреты сессии и удаления
- **THEN** сервер не позволяет восстановить их по IP, содержимому поста или публичному идентификатору автора
