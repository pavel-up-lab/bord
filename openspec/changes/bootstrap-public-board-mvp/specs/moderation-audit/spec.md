# Spec Delta

## Purpose

Определяет контролируемую модерацию публичной борды, ограниченный доступ к anti-abuse данным и проверяемый аудит административных действий.

## ADDED Requirements

### Requirement: Аутентифицированные административные операции
Система SHALL требовать отдельный административный credential для просмотра очереди жалоб, скрытия публикаций, закрытия тредов и управления блокировками.

#### Scenario: Неавторизованный административный запрос
- **WHEN** запрос административной операции не содержит действительный credential
- **THEN** система отклоняет его и не раскрывает административные данные

### Requirement: Модерация контента
Уполномоченный модератор SHALL иметь возможность скрыть пост, закрыть тред и восстановить ошибочно скрытый пост, указав причину действия.

#### Scenario: Скрытие поста
- **WHEN** модератор скрывает видимый пост с причиной
- **THEN** публичное API возвращает tombstone, вложение становится недоступно, а действие появляется в аудите

### Requirement: Блокировки источников
Уполномоченный модератор SHALL иметь возможность создать ограниченную по сроку блокировку IP, IP-префикса или IP-индекса для выбранных операций и досок.

#### Scenario: Истечение блокировки
- **WHEN** время окончания блокировки прошло
- **THEN** система перестает применять ее без удаления аудиторской записи

### Requirement: Защищенное хранение IP
Система MUST сохранять для anti-abuse поиска HMAC IP и, только при включенной политике, зашифрованный исходный IP; ключ HMAC и ключ шифрования MUST быть независимы от базы данных.

#### Scenario: Обычный просмотр поста модератором
- **WHEN** модератор просматривает публикацию без отдельной операции раскрытия IP
- **THEN** система не возвращает исходный IP

#### Scenario: Разрешенное раскрытие IP
- **WHEN** уполномоченный администратор запрашивает IP с обязательной причиной
- **THEN** система расшифровывает IP только для этого ответа и записывает факт доступа в аудит

### Requirement: Проверяемый аудит
Система SHALL записывать административные входы, изменения контента, блокировки и доступ к IP с субъектом, временем, целью, результатом и идентификатором запроса.

#### Scenario: Ошибочная административная операция
- **WHEN** административная операция отклонена
- **THEN** аудит содержит неуспешный результат, но не содержит credential, ключи или расшифрованный IP

### Requirement: Срок хранения IP-данных
Система SHALL автоматически удалять зашифрованные IP и связанные технические идентификаторы по окончании настраиваемого срока, по умолчанию 90 дней, если сохранение не требуется действующей блокировкой или расследованием.

#### Scenario: Плановая очистка
- **WHEN** IP-данные старше срока и не имеют действующего основания сохранения
- **THEN** система безвозвратно удаляет исходный шифротекст и фиксирует агрегированный результат очистки
