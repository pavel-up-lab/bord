# Spec Delta

## Purpose

Определяет доступный клавиатурный TUI в ретростиле с предсказуемой навигацией по доскам, тредам и вложениям на современных терминалах.

## ADDED Requirements

### Requirement: Двухпанельная навигация
Клиент SHALL показывать слева список досок, а справа каталог выбранной доски или открытый тред, с явно обозначенной активной панелью.

#### Scenario: Переключение панелей
- **WHEN** пользователь нажимает `Tab`
- **THEN** фокус переходит в другую панель без потери выбранного элемента и позиции прокрутки

#### Scenario: Узкое окно
- **WHEN** ширины терминала недостаточно для двух панелей
- **THEN** клиент переходит в однопанельный режим с доступной командой возврата

### Requirement: Полное управление с клавиатуры
Клиент MUST предоставлять чтение, навигацию, создание треда, ответ, обновление, поиск, открытие вложения, справку и выход без мыши.

#### Scenario: Просмотр справки
- **WHEN** пользователь нажимает `?`
- **THEN** клиент показывает актуальные сочетания для текущего экрана и позволяет вернуться без изменения состояния

### Requirement: Редактор публикации
Клиент SHALL предоставлять многострочный редактор с явной отправкой, отменой и отображением ограничений текста и вложения.

#### Scenario: Ошибка отправки
- **WHEN** сервер отклоняет публикацию или сеть недоступна
- **THEN** введенный текст и выбранное вложение остаются в редакторе, а клиент показывает безопасную причину и возможность повтора

### Requirement: Сохранение локального состояния
Клиент SHALL безопасно сохранять адрес сервера, пользовательские настройки и локальные секреты в каталоге конфигурации ОС с ограниченными правами доступа, где это поддерживается.

#### Scenario: Повторный запуск
- **WHEN** пользователь запускает клиент после штатного выхода
- **THEN** клиент восстанавливает настройки и последнюю выбранную доску, не записывая секреты в журнал

### Requirement: Кроссплатформенное поведение
Клиент SHALL поддерживать Linux, macOS и современный Windows Terminal и SHALL использовать нативный механизм ОС для открытия внешнего файла.

#### Scenario: Открытие файла в Windows
- **WHEN** пользователь в Windows Terminal открывает загруженное вложение внешне
- **THEN** клиент передает локальный файл системной ассоциации Windows без выполнения имени файла как команды shell

### Requirement: Управляемое завершение
Клиент MUST восстанавливать состояние терминала после штатного выхода, отмены, ошибки верхнего уровня и поддерживаемых сигналов завершения.

#### Scenario: Аварийная ошибка интерфейса
- **WHEN** клиент не может продолжить работу из-за внутренней ошибки
- **THEN** он покидает alternate screen, восстанавливает ввод и выводит краткий идентификатор ошибки
