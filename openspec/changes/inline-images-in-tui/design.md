# Design

## Context

См. `proposal.md` — Why и `specs/terminal-image-rendering/spec.md`. Сейчас `internal/terminalui.KittyViewerCommand` запускается через `tea.Exec`, очищает экран и ждет `Enter`; ANSI уже формируется как доверенные строки внутри `attachmentRows`. Подготовка изображения проверяет MIME, размер, SHA-256 и границы декодирования до renderer. Bubble Tea v1.3 управляет alternate screen и построчно пропускает неизменившиеся строки, поэтому нативное изображение должно участвовать в кадре TUI, а не конкурировать с renderer за stdout.

## Goals / Non-Goals

**Goals:**

- единый встроенный pipeline для пользовательского и административного TUI;
- качественная графика в поддерживаемых терминалах без потери управления;
- детерминированный ANSI fallback при любой неопределенности;
- ограниченный и тестируемый жизненный цикл terminal resources;
- отсутствие обязательной установленной программы для автоматического режима.

**Non-Goals:**

- анимация, видео, GIF и несколько одновременно видимых вложений;
- гарантированная pixel-графика во всех терминалах и мультиплексорах;
- изменение серверного API, форматов или лимитов вложений;
- поддержка произвольных terminal graphics escape-последовательностей из входных данных.

## Decisions

### 1. Общий frame renderer вместо отдельного viewer

`internal/terminalui` получит общий renderer, который принимает только уже проверенное изображение, доступный прямоугольник и terminal capabilities, а возвращает ограниченные по ширине строки кадра, фактический режим и управляющие данные очистки. `internal/tui` и `internal/admintui` будут вставлять эти строки как `TrustedANSI` в панель вложения.

Kitty и Sixel больше не запускаются автоматически через `tea.Exec`. `w3m` и системный opener останутся отдельными явно вызываемыми действиями. Это сохраняет один владеющий stdout компонент — Bubble Tea — и исключает гонки между двумя полноэкранными renderer.

Альтернатива: писать escape-последовательности отдельной командой поверх Bubble Tea. Она отклонена, потому что асинхронная перерисовка может стереть или сместить изображение.

### 2. Kitty через виртуальное размещение и Unicode placeholders

Kitty backend передает PNG с уникальным для открытого вложения image ID, создает виртуальное placement (`U=1`) и выводит прямоугольник `U+10EEEE` с кодированными image ID, строкой и колонкой. Placeholder-ячейки становятся обычной частью `View()`: Bubble Tea сохраняет их координаты, перемещает при resize и может безопасно окружать текстом.

Передача выполняется в первом доверенном ряду поколения кадра и использует quiet mode. ID выводится только из внутреннего счетчика/хэша проверенного attachment ID; пользовательские байты никогда не интерполируются в control data. При замене поколения сначала включается delete-команда предыдущего ID.

Альтернатива: обычное Kitty placement в позиции курсора. Оно отклонено, потому что позиция не связана с текстовыми ячейками Bubble Tea и легко рассинхронизируется.

### 3. Sixel как второй нативный backend

Sixel backend масштабирует декодированное изображение в пиксельные границы зарезервированных строк, кодирует его pure-Go библиотекой `github.com/mattn/go-sixel` и помещает DCS payload в первый доверенный ряд области. Остальные строки резервируют высоту. Payload формируется заново только при открытии, resize или смене режима; неизменившийся кадр может быть пропущен Bubble Tea.

Зависимость должна быть закреплена конкретной версией, пройти проверку лицензии, `govulncheck`, fuzz на ограниченных изображениях и кросс-компиляцию без CGO. Внешний `img2sixel` не используется.

Альтернатива: собственный Sixel encoder. Она отклонена как недоменная реализация сложного квантования и кодирования с лишней поверхностью ошибок.

### 4. Консервативное определение возможностей до запуска TUI

Новый detector работает до `tea.Program.Run`, имеет ограниченный таймаут и возвращает immutable-набор возможностей. Kitty требует успешного протокольного probe и принадлежности к проверенному семейству/версии с Unicode placeholders. Sixel подтверждается ответом terminal device attributes. Переменные окружения используются как подсказка для выбора probe, но не как единственное доказательство.

Если stdin/stdout не являются TTY, ответ неполон, запуск идет через неподдерживаемый multiplexer или истекает таймаут, detector возвращает только ANSI. Probe-ответы не должны попадать в последующий пользовательский ввод Bubble Tea.

Detector и transport являются интерфейсами, чтобы тесты использовали фиктивные ответы без реального терминала. Для `tmux`/`screen` нативный режим разрешается только после успешного passthrough probe.

Альтернатива: текущая проверка только `TERM`/`TERM_PROGRAM`. Она отклонена из-за ложноположительных результатов через SSH, tmux и старые версии терминалов.

### 5. Выбор режима и совместимая миграция настройки

`InlineMode` расширяется значением `sixel`. Значения `auto`, `kitty`, `sixel`, `ansi`, `w3m`, `off` остаются строковыми и совместимыми с существующими state-файлами. `auto` использует Kitty → Sixel → ANSI. Принудительный нативный режим ограничивает выбор заданным протоколом, но при неподтвержденной поддержке безопасно показывает ANSI и предупреждение.

Окно настроек показывает автоматический режим и отдельные явные варианты. Экран вложения всегда сообщает фактический backend, например `Изображение: Kitty`, `Изображение: Sixel` или `Изображение: ANSI`.

### 6. Жизненный цикл принадлежит terminal session

Session хранит активные Kitty image/placement IDs и generation. Переход назад, новое вложение, resize и смена режима формируют cleanup до нового кадра. Для Sixel очисткой служит перерисовка зарезервированной области; при полном выходе выполняется очистка экрана, которой уже управляет Bubble Tea.

Entrypoints создают detector/session до модели и обязательно вызывают `Close` после `Program.Run`, включая ошибки и отмену context. Cleanup идемпотентен и содержит только внутренние фиксированные последовательности. Интегрированный `bord-admin` разделяет одну terminal session между пользовательским и административным режимами, чтобы placements не переживали переключение режима.

### 7. ANSI остается немедленным универсальным представлением

Существующий true-color half-block renderer остается встроенным и не требует протокольного probe. Пока нативный кадр готовится либо если его создание завершилось ошибкой, экран показывает ANSI-версию или индикатор загрузки в зависимости от доступных данных. Ошибка нативного backend не закрывает экран и не блокирует внешнее открытие проверенного файла.

## Risks / Trade-offs

- [Поддержка Kitty placeholders различается по версиям терминалов] → консервативный allowlist после активного probe, ANSI fallback и матрица ручных smoke-тестов.
- [Sixel payload велик и может замедлять перерисовку] → масштабирование до области, ограничение палитры библиотекой, кэш по attachment/размеру и генерация только при изменениях.
- [Bubble Tea может изменить правила обработки APC/DCS] → изолированные golden-тесты полного кадра и terminal smoke при обновлении зависимости.
- [tmux/screen могут фильтровать управляющие последовательности] → по умолчанию ANSI без успешного passthrough probe.
- [Нативная картинка может остаться после аварийного kill -9] → следующий запуск начинает с очистки принадлежащего диапазона Kitty IDs; для неустранимого `kill -9` гарантии нет.
- [Pure-Go Sixel dependency увеличит размер бинарника] → измерить размер release и оставить ANSI fallback, если зависимость не пройдет аудит.

## Migration Plan

1. Добавить detector и новые capability/session abstractions, сохранив текущий viewer за feature fallback.
2. Подключить Kitty placeholders и ANSI в пользовательском TUI, затем в admin TUI.
3. Добавить и проверить Sixel backend на Windows Terminal.
4. Мигрировать настройки и CLI help, после чего отключить автоматический `tea.Exec` viewer.
5. Выпустить новую клиентскую версию и обновить лендинг только после smoke на Kitty, iTerm2/WezTerm и Windows Terminal.

Rollback: вернуть прежний отдельный viewer, не меняя state-файлы; неизвестное старой версии значение `sixel` уже должно нормализоваться в `auto` существующей логикой валидации.
