# Proposal

## Why

Пользователи не понимают текущий просмотр изображений: нативный режим временно покидает полноэкранный интерфейс, а доступные действия и различия между режимами неочевидны. Изображение должно быть частью экрана вложения, сохранять навигацию TUI и автоматически выбирать лучший поддерживаемый терминалом способ отображения.

## What Changes

- Показывать изображение непосредственно в выделенной области экрана вложения без автоматического перехода в отдельный viewer.
- Добавить встроенное размещение через Kitty graphics protocol с Unicode placeholders для совместимых терминалов.
- Добавить Sixel-рендеринг для Windows Terminal и других терминалов с подтвержденной поддержкой.
- Использовать встроенный ANSI half-block renderer как автоматический fallback внутри TUI.
- Определять графические возможности терминала до выбора renderer и показывать активный режим пользователю.
- Корректно удалять нативные изображения при уходе с экрана, изменении размеров, смене режима и завершении программы.
- Оставить открытие системным приложением отдельным явным действием.

## Capabilities

### New Capabilities

- `terminal-image-rendering`: отображение проверенных изображений внутри TUI через Kitty, Sixel или ANSI с автоопределением, жизненным циклом placements и внешним fallback.

### Modified Capabilities

Нет.

## Impact

- `internal/terminalui`: capability detection, Kitty placeholder renderer, Sixel encoder/renderer и общий lifecycle нативного изображения.
- `internal/tui` и `internal/admintui`: экран вложения, команды показа, resize/cleanup и индикация режима.
- `internal/clientapp` и `internal/adminapp`: настройка режима и инициализация terminal capabilities.
- Тесты терминального вывода и smoke-матрица Linux/macOS/Windows.
- Пользовательская документация и инструкции лендинга.
- Публичный HTTP API и формат вложений не меняются; новая обязательная внешняя зависимость не добавляется.
