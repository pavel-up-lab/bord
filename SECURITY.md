# Security policy

## Поддерживаемые версии

Исправления безопасности выпускаются для последнего опубликованного релиза и
актуальной ветки `main`. Старые версии следует обновлять перед обращением.

## Сообщение об уязвимости

Не публикуйте сведения об уязвимости в обычном GitHub Issue, треде публичной
борды или pull request.

Используйте **Security → Report a vulnerability** в GitHub-репозитории. В
сообщении укажите:

- затронутую версию или commit;
- минимальные шаги воспроизведения;
- возможное влияние;
- безопасный proof of concept без чужих данных и действующих секретов;
- известные способы временного ограничения риска.

Если private vulnerability reporting временно недоступен, напишите на
`pavel.poroshin.developer@gmail.com` с темой `Bord security report`.

Мы постараемся подтвердить получение в течение 7 дней. Срок исправления зависит
от серьёзности и сложности проблемы. Не проводите нагрузочные проверки
публичного сервиса и не извлекайте, не изменяйте и не публикуйте чужие данные.

## Область ответственности

К security-проблемам относятся обход moderation/admin boundary, раскрытие IP или
секретов, подмена trusted proxy, обход лимитов загрузки, path traversal,
инъекции, нарушение delete capability и удалённое выполнение кода.

Ошибки интерфейса без влияния на конфиденциальность, целостность или доступность
можно оформлять обычным Bug report.
